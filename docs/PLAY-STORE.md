# 구글 플레이스토어 등록 가이드 — 이모티학

> 2026-11-06 기준. 선택한 모델은 **일회성 유료 다운로드 + TWA 크레딧 무차감**입니다. 웹의 기존 크레딧·토스 결제는 유지합니다. 이 문서는 코드 구현과 Console/기기에서만 가능한 작업을 구분합니다.
>
> 분석 폴백, 카카오 공유, 오프라인 서비스 워커와 접근성 결정은 [FAILSAFE-SHARING-TWA.md](./FAILSAFE-SHARING-TWA.md)를 함께 확인하세요.

## 1. 현재 구현된 범위

| 기능 | 일반 웹 | TWA 환경 | 관리자 |
|---|---|---|---|
| 크레딧 | 컷·다시 그리기당 차감 | 차감 없음 | 차감 없음 |
| 스타일·24컷·워터마크·브리핑 | 플랜별 | 전체 기능 | 전체 기능 |
| 디지털 크레딧 주문 | 토스(설정된 경우) | 서버 409 차단 | 차단 |
| 속도 제한 | 적용 | **적용** | 예외 |
| AI 공정 이용 | 크레딧 기준 | **KST 일일 생성 시도 96회 기본값** | 예외 |

- `PLAY_DAILY_GENERATION_LIMIT`으로 기본 한도를 조정할 수 있습니다. 사진 준비, 시안, 컷, 다시 그리기 및 배치 생성은 실제 생성 직전에 시도 수를 소비합니다. 이미 생성된 이미지를 다시 읽는 요청은 소비하지 않습니다.
- `/billing`은 Play 사용자에게 “무제한”이 아니라 **크레딧 차감 없음 + 오늘의 AI 사용량**을 표시합니다.
- **중요:** `TWA/` UA는 위조할 수 있는 환경 신호이며 구매 증명이 아닙니다. 현재의 크레딧 무차감 혜택도 이 신호를 사용하므로, 공정 이용 한도는 원가 완화 장치일 뿐 유료 구매·환불 검증을 대신하지 않습니다. 실제 유료 출시 전에 Play 라이선스 검증과 환불 후 접근 회수를 구현하거나 이 위험을 명시적으로 해소해야 합니다.

관련 코드: `src/lib/twa.ts`, `src/middleware.ts`, `src/lib/session.ts`, `src/lib/admin-access.ts`, `src/lib/play-usage.ts` 및 생성 API 라우트.

## 2. 계정 삭제와 AI 신고

### 계정 및 데이터 삭제

- 공식 외부 경로: **<https://emotihak.com/account-deletion>**
- 로그인 후 현재 비밀번호와 확인 문구를 다시 검증하는 same-origin `DELETE /api/auth/account`를 제공합니다.
- 계정·세션·얼굴/일관성 준비 정보·시안·팩·생성 이미지·브리핑·신고·Play 사용량을 삭제합니다.
- 미해결 결제, 결제/원장 불일치, 제작·배송 중인 상품 주문이 있으면 삭제를 차단하고 먼저 정리하도록 안내합니다.
- 법정 보존이 필요한 유료 주문과 구매·환불 원장만 남기고, 배송·연락처·추적 정보·상품 이미지·썸네일은 제거합니다.
- 이미지 바이트 삭제는 영속 작업으로 기록하며 계정 삭제, 운영 숨김, 정리 크론에서 재시도합니다. 숨기거나 삭제한 컷은 이미지 URL에서도 접근할 수 없습니다.
- 로그인할 수 없는 사용자를 위한 고객센터 이메일 경로도 같은 페이지에 제공합니다. 비밀번호·카드 정보는 요청하지 않습니다.

### 생성형 AI 결과 신고

- 각 AI 컷과 편집기의 **신고** 버튼으로 앱을 떠나지 않고 사유·상세 설명을 접수합니다.
- 신고는 컷 소유자만 접수할 수 있고, 중복 접수와 요청 빈도를 제한합니다.
- `/admin`의 **AI 콘텐츠 신고** 큐에서 검토 완료·기각·콘텐츠 숨김을 처리합니다.
- 숨긴 컷은 팩 뷰에서 제외합니다. `PackViewer`가 누락 컷을 자동 재생성하므로 이미지 ID만 지우는 방식은 사용하지 않습니다.
- 운영자는 열린 신고에 연결된 이미지만 검토용으로 볼 수 있으며, 숨긴 이미지는 소유자·운영자 모두에게 404로 차단됩니다.

## 3. 서명과 도메인 연결

- 과거 Git에 추적됐던 업로드 키는 삭제하고 새 RSA 4096 업로드 키로 교체했습니다. **Git 이력에 남은 이전 키는 폐기합니다.**
- 새 개인 키·비밀번호·인증서는 `twa/private/`에만 있고 Git에서 제외됩니다. 이 디렉터리는 로컬 비밀 자료이며 PR에 포함되지 않습니다.
- `scripts/prepare-play-signing.mjs`는 OpenSSL만으로 키를 준비하고 공개 설정을 갱신합니다. 비밀번호를 출력하거나 AAB를 생성하지 않습니다.
- `twa/twa-manifest.json`은 `private/android-keystore.p12`, alias `emotihak`을 사용합니다.
- `public/.well-known/assetlinks.json`에는 새 업로드 인증서 지문이 등록돼 있습니다. 웹 배포 후 실제 URL에서 확인해야 합니다.
- Play App Signing의 **앱 서명 인증서 지문은 아직 알 수 없습니다.** 첫 AAB 업로드 후 Console에서 확인해 기존 지문을 유지한 채 추가합니다.

```bash
node scripts/update-assetlinks.mjs "PLAY:APP:SIGNING:SHA256:..."
```

자세한 키 보관·회전 절차는 `twa/README.md`를 참고하세요.

## 4. AAB 빌드와 기기 검증 (외부 작업)

이 저장소에는 TWA 프로젝트와 매니페스트가 있지만 **AAB/APK는 생성되지 않았습니다.** JDK 17, Android SDK, Bubblewrap이 있는 로컬 환경에서 수행합니다.

```bash
npm i -g @bubblewrap/cli
cd twa
bubblewrap build --aab
```

확인 항목:

- [ ] AAB가 새 업로드 키로 서명됐는지 확인하고 난독화/업로드 무결성 검사를 수행
- [ ] 내부 트랙 설치 후 TWA가 크롬 탭이 아닌 독립 앱으로 열리는지 확인
- [ ] Asset Links 검증과 Play 앱 서명 지문 추가 후 딥링크 확인
- [ ] 앱에서 크레딧 차감 없음, 일일 AI 공정 이용 표시, 24컷, 워터마크 없음 확인
- [ ] 같은 계정의 일반 웹에서는 기존 크레딧·결제 동작이 유지되는지 확인
- [ ] 실제 Gemini 유료 호출의 지연·실패·재시도·원가를 확인(데모/스텁과 구분)
- [ ] 비행기 모드에서 오프라인 페이지가 표시되고 API·사적 결과가 캐시되지 않는지 확인
- [ ] 내비게이션 뒤로가기·루트 종료·생성 중 경고와 사진 촬영 전 사전 고지를 확인
- [ ] 카카오 Feed(키를 설정한 경우), 시스템 공유, 비회원 결과, App Link/Play 대체와 링크 해제를 확인
- [ ] 신고 접수→운영 숨김→앱에서 사라지는 흐름과 계정 삭제를 실제 원격 저장소에서 확인

## 5. Play Console 체크리스트 (사용자 권한 필요)

1. 개발자 계정, $25 등록비, 신원/조직 인증을 완료합니다.
2. **유료 앱 판매에 필요한 결제(판매자) 프로필**, 세금 양식, 정산 계좌를 연결합니다.
3. 앱을 처음부터 **유료**로 만들고 국가별 가격(제안: 한국 ₩4,900)을 설정합니다. 무료로 만든 앱의 가격 모델 전환 제약을 확인합니다.
4. 스토어 목록, 512×512 아이콘, 1024×500 피처 그래픽, **기기 스크린샷 최소 2장 이상**을 등록합니다. 현재 피처 그래픽은 초안이고 실제 기기 스크린샷 세트는 별도 제작이 필요합니다.
5. 개인정보처리방침 URL, 계정 삭제 URL, 데이터 안전 양식을 실제 SDK·제공자 설정과 대조해 작성합니다. 사진이 Gemini로 전송되는 사실과 계정/생성물/신고/공정 이용 기록을 누락하지 마세요.
6. 생성형 AI 정책, 콘텐츠 등급, 광고 여부, 앱 액세스, 대상 연령, 뉴스/건강 등 해당 선언을 완료합니다.
7. target API 36 설정을 확인합니다. 현재 TWA는 minSdk 24, target/compileSdk 36입니다.
8. 내부/비공개 테스트를 진행합니다. 해당하는 신규 개인 개발자 계정은 **12명 이상, 연속 14일** 테스트 요건이 있을 수 있으므로 Console에 표시되는 요건을 확인합니다.
9. 프로덕션 제출 전 환불·라이선스 정책을 확정합니다. 환불 후에도 설치된 앱의 혜택을 회수하는 코드는 아직 없습니다.
10. 통신판매업 신고 정보와 최종 법률 검토를 완료합니다. 저장소의 임시 문구나 로컬 테스트 통과를 법적 승인·출시 승인으로 간주하지 마세요.

## 6. 스토어 목록 초안

**제목:** 이모티학 — AI 이모티콘

**짧은 설명:**

```text
사진 한 장이면 얼굴이 이모티콘이 됩니다. 11가지 스타일·24컷 팩·카톡 저장까지 — 이모티학
```

**전체 설명:**

```text
사진 한 장이면, 얼굴이 나만의 이모티콘이 됩니다 — 이모티학

셀카 한 장으로 나만의 캐릭터를 만들고, 표정과 대사를 편집해 카카오톡에 저장하세요.

[한 번 구매에 포함]
11가지 스타일, 24컷 팩, 대사·표정·소품 편집, 워터마크 없는 내보내기, 카카오 규격 검증·ZIP을 제공합니다. 앱에서 디지털 크레딧을 추가 판매하지 않으며, AI 생성에는 일일 공정 이용 한도가 적용됩니다.

[이용 방법]
1. 사진을 선택하고 얼굴 특징을 확인합니다.
2. 2D 캐릭터·3D 클레이·수채화·스케치·픽셀아트 등 스타일을 고릅니다.
3. 대사·표정·소품을 편집합니다.
4. 360×360 PNG 또는 카카오 제안 규격 ZIP으로 저장합니다.

[안전과 개인정보]
AI가 만든 결과는 사용 전에 확인해 주세요. 부적절한 결과는 각 컷의 신고 버튼으로 알릴 수 있습니다. 계정과 연관 데이터는 앱·웹의 계정 삭제 페이지에서 직접 삭제할 수 있습니다. 사진과 생성 과정에 관한 자세한 내용은 개인정보처리방침을 참고해 주세요.

웹(emotihak.com)에서는 별도 크레딧 이용 방식도 제공합니다.
```

> 스토어 문구는 최종 기능·법률 검토 후 확정하고, 공정 이용 한도를 숨기거나 “완전 무제한”으로 광고하지 마세요.

## 7. 검증 명령

```bash
npm run typecheck
npm run test:failsafe
npm run test:play:static
rm -rf /tmp/emotime-play-lib
DATA_DIR=/tmp/emotime-play-lib STORE_BACKEND=file npm run test:play

# 별도 격리 개발 서버에서:
PLAY_TEST_BASE_URL=http://localhost:3000 node scripts/e2e-play.mjs
AUTH_TEST_BASE_URL=http://localhost:3000 ADMIN_PASSCODE=... node scripts/test-auth.mjs
```

테스트는 파일 저장소·데모 AI를 사용합니다. Play 라이선스 검증, 실제 Toss/Gemini, Cloudflare KV, 서명된 AAB, 실제 기기 또는 Console 완료를 증명하지 않습니다.
