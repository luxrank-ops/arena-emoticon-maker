# 구글 플레이스토어 등록 가이드 — 이모티학 (유료 앱)

> 2026-11 기준. 모델: **유료 앱(일회성 다운로드 결제)** + **TWA = 모든 기능 무제한**.
> 웹(emotihak.com)은 기존 그대로(무료 + 토스 크레딧 충전).

## 1. 모델 선택 — 왜 "유료 앱"인가

|안|결제 방식|TWA에서 실현 가능성|
|---|---|---|
|**유료 앱(선택)**|다운로드 시 일회성 결제 — **구글이 처리**|✅ **코드 불필요**. 결제는 Play가 다운로드 단계에서 막아주므로 앱 안의 검증 코드가 없음|
|무료 앱 + 인앱구매(IAP)|앱 안에서 크레딧/구독 구매|❌ Play Billing SDK가 네이티브 코드 필요. 평범한 Bubblewrap TWA로는 불가 → 커스텀 TWA 또는 Capacitor로 앱 구조 교체해야 함|

**결론:**
- 앱은 **일회성 유료 다운로드**(제안가 4,900원 — 콘솔에서 국가별 가격 티어로 조정).
- 앱(안드로이드 TWA) 안에서는 **모든 기능 무제한** — 크레딧 차감 없음, 스타일 11종 전체, 워터마크 제거, 24컷 팩, 카카오 규격 패키징, Daily Brief, 굿즈 할인, 요청 제한 면제.
- 결제를 앱에서 다시 거칠 필요가 없으므로 **Play Billing / IAP 정책 문제를 근본적으로 회피**한다.
- 웹(emotihak.com)은 Play 관할 밖이라 **토스페이먼츠 크레딧 충전 유지** (변경 없음).

**수익 구조 특성:** 일회성 매출(구독 아님). 구독/크레딧 확장 원하면 §7 참조.

## 2. 플레이 앱 풀액세스 판정 방식 (이번 PR 구현)

```
TWA WebView (UA에 "TWA/1.0" 토큰 포함)
  → src/middleware.ts : UA 감지 → 요청 헤더 x-emotihak-play: 1 추가
  → src/lib/session.ts getCurrentUser() : 헤더 확인 → user.play = true
      (매 요청 결정되는 임시 플래그 — DB 에 영속화하지 않음)
  → src/lib/admin-access.ts : admin 또는 play = isFullAccess → STUDIO 대우
```

|기능|일반 웹 사용자|플레이 앱 사용자|관리자|
|---|---|---|---|
|크레딧 차감|컷당 1|**없음(무제한)**|없음|
|스타일|7종|**11종 전체**|11종 전체|
|24컷 팩|크레딧 24 필요|**무제한**|무제한|
|워터마크|FREE: 있음|**없음**|없음|
|카카오 규격 패키징(STUDIO+)|X|**O**|O|
|Daily Brief(PLUS+)|X|**O**|O|
|굿즈 할인|플랜별|**STUDIO 할인**|STUDIO 할인|
|요청 제한(Rate limit)|적용|**면제**|면제|
|플랜 표시|FREE/PLUS/STUDIO|**PLAY**|관리자|
|운영 콘솔(metrics/purge)|X|**X**|O|

- **영속화하지 않는 이유:** 같은 계정을 웹에서 쓰면 풀액세스가 누설되어서는 안 되므로, TWA 요청일 때만 플래그가 붙는다.
- **구매 UI 차단:** TWA에서 pricing 페이지는 "모든 기능을 이용 중이에요" 안내로 대체되고, 크레딧 주문 생성은 서버가 409(`IAP_POLICY_RESTRICTED`)로 방어한다. 물리 굿즈 주문은 앱 안에서도 웹 결제 허용(유형별: 디지털=차단, 물리=허용).
- **검증 스크립트:**
  - `scripts/e2e-play.mjs` — HTTP E2E (dev 서버 실행 필요. TWA UA vs 웹 UA 비교)
  - `scripts/e2e-play-lib.ts` — lib 레이어 통합 테스트 (서버 정지 상태에서 `npx tsx scripts/e2e-play-lib.ts`)

### [ ] 4-3. TWA 빌드 (사용자 로컬 — JDK 17 + Android SDK 필요)
> **샌드박스에서는 불가**: Android SDK/Gradle 의존성이 `dl.google.com`·`services.gradle.org` 에서 받아야 하는데 샌드박스 네트워크가 차단되어 있다. 그래서 **프로젝트(`twa/`)·서명 키·매니페스트는 이미 생성돼 있고, 사용자 로컬에서 `build --aab` 한 줄만** 남는다.

`bubblewrap init`·서명 키는 이미 완료된 상태(`twa/` 참고). 본인 머신에서:
```bash
npm i -g @bubblewrap/cli   # JDK 17 이 없으면 프롬프트로 자동 설치 제안
cd twa
bubblewrap build --aab
# 산출물: dist/*.aab   (빌드 시 저장소/키 비밀번호 입력 — twa/keystore-passwords.txt)
```
- 산출물: **AAB(App Bundle)** — 플레이스토어는 APK 를 받지 않음.
- 프로젝트: compileSdk/targetSdk **36**(최신) · minSdk 24 · Gradle 8.11.1. Play 의 최신 타겟 API 요건에 자동으로 부합.
- 서명 키: 업로드 키 `android-keystore.p12`(alias `emotihak`, RSA 4096, 25년) / 백업 키 `backup-keystore.p12`(git 제외 — **반드시 별도 보관**).

### [ ] 4-4. Digital Asset Links (도메인 검증)
> **업로드 키 SHA-256 지문은 이미 `public/.well-known/assetlinks.json` 에 기입 완료.**

1. 메인 머지 → 배포 후 <https://emotihak.com/.well-known/assetlinks.json> 접근 확인.
2. Asset Links 검증자(<https://developers.google.com/digital-asset-links/tools/validator>)로 확인.
3. ⚠️ **Play 앱 서명(Play App Signing) 추가 지문** — 신규 앱은 자동 가입되며, 설치된 앱은 **Play 서명 키**로 서명된다(업로드 키 아님). 첫 AAB 업로드 후 콘솔 **앱 무결성 → 앱 서명** 에서 Play 서명 키의 SHA-256 지문을 확인해:
   ```bash
   node scripts/update-assetlinks.mjs "AA:BB:CC:..."
   ```
   로 `assetlinks.json` 에 **추가** 후 재배포 (두 지문 모두 함께 유효).
4. **TWA 안의 UA** 에 `TWA/1.0` 이 포함되면 풀액세스가 활성화되는지 앱에서 직접 확인 (요금제 페이지에 "모든 기능을 이용 중이에요" 표시).

## 5. 환불 — 유료 앱의 특성 (반드시 숙지)

- **Play 표준 환불 정책:** 사용자가 구매 후 **48시간 이내**에 요청하면 **자동 환불**된다.
- 환불되어도 **앱은 설치된 채로 남아 있고**, 우리는 설치/구매 상태를 거두는 코드가 없으므로 **환불 후에도 앱은 계속 동작**한다.
- v1 에는 이 위험을 받아들인다 (1인 개발, 일회성 저가, UA 위조 위험과 같은 등급의 잔존 리스크).
- 악용이 현실화하면 §7의 하드닝(LVD)으로 "구매 상태 검증"을 추가해 환불 후 동작을 제한할 수 있다.

## 7. 보안 한계와 향후 하드닝

**현재 방식의 한계 (v1 에 명시적으로 수용):**
- TWA 판정은 **UA 문자열(`TWA/1.0`) 기반**이다. 브라우저에서 UA 를 TWA 로 위조하면 Play 에 구매하지 않아도 풀액세스를 받을 수 있다. (물리적으로 "진짜 TWA" 와 구별 불가)
- v1 수용 근거: 위조는 의도적 조작이 필요하고, 손실 규모는 웹 크레딧 1~2팩 수준. 유료 앱 가격(4,900원) 대비 낮은 위험.

**하드닝 경로 (악용이 확인되면 순서대로):**
1. **커스텀 TWA + Google Play License Verification (LVD)** — 유료 앱의 정석. 네이티브 셸이 Google 라이선스 서버와 구매 상태를 검증한다. (Bubblewrap 기본 셸로는 불가 → 자체 TWA 빌드)
2. **Play Developer API 로 구매 상태 검증** — 서버가 주문/구입 기록을 확인(구독은 이경로에 잘 맞음. 일회성 구매는 LVD 가 더 적합).
3. **단기 완화** — 풀액세스 경로(24컷·수채화 등)에 별도 엄격 rate limit + 이상 사용 모니터링.

**AI 원가 유의:** 유료 앱 사용자는 무제한 생성이므로 Gemini 호출 비용이 그대로 나간다. 원가가 문제가 되면 "공정 이용" 상한(예: 월 N컷)을 play 사용자에도 적용할 수 있다 (`bypassesRateLimit`/`isUnlimited` 단일 지점 수정으로 가능).

## 9. 향후 수익 확장 (필요 시)

- **앱 내 구독/크레딧(IAP):** TWA 를 Capacitor 또는 커스텀 TWA 로 교체 + Play Billing SDK 통합. 그때부터 앱=IAP 만, 웹=토스 유지(병존 허용).
- **공정 이용 상한:** §7 참조.
- **Apple(App Store) 대응:** iOS 는 TWA 가 아니라 WKWebView 앱(앱클립/웹클립 계열) + StoreKit 또는 웹 결제로 별도 검토 필요.
