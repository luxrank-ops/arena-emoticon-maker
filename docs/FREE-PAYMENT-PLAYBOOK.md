# 무료로 결제 시스템 탑재하기 — 실행 플레이북

> 작성: 2026-11-24 · 범위: `이모티학(EmotiHak)` 웹·PWA·TWA
> 결론 먼저: **결제 코드는 이미 다 있다. 지금 막고 있는 건 코드가 아니라 사업자등록·PG 계약이다.**
> 그래서 "무료"는 두 가지로 나눠서 푼다 — ① 0원으로 지금 바로 매출이 나는 경로(교환권), ② 나중에 PG를 붙일 때 돈이 안 드는 조합.

## 2. 왜 "무료 결제"가 원래는 불가능한가 (2026년 기준)

- 국내 PG(토스페이먼츠·KG이니시스·나이스페이·헥토)는 **사업자등록 필수**다. 개인 명의로는 가맹 계약이 안 된다. ([토스 가입 절차](https://modumvp.com/guide/toss-payments-integration/))
- 가입비·연회비는 대개 무료지만 **카드사 심사에 최대 10~14영업일**이 걸리고, 사이트에 사업자 정보·통신판매업 신고번호·고객센터가 없으면 반려된다. (같은 출처)
- 수수료는 매출에서 나가므로 "고정비"는 아니지만, **결제가 안 되면 매출도 0** 이라는 게 진짜 문제다.
- 포트원(PortOne)은 **월 거래액 5천만 원 미만 Free 플랜**이지만, 포트원도 PG 계약 자체를 대신해 주지 않는다. 즉 사업자 문제는 그대로다. ([포트원 요금](https://agentic30.app/blog/portone-guide))
- 스토어(구글 플레이) 인앱결제도 **개발자 계정 + 상품 등록**이 필요하고, 디지털 상품은 15~30% 수수료가 붙는다.

→ 결론: **사업자 없이 카드결제를 "합법적으로" 붙이는 방법은 없다.** 대신 **사업자 없이 지금 돈을 받는 방법**은 있다. 그게 3번이다.

## 3. 0원 · 오늘 바로 — 교환권(코드) 결제  ⭐ 구현 완료

### 3.1 개념

PG를 쓰지 않고 **입금 확인 → 코드 발급 → 사용자가 코드 입력 → 즉시 지급** 구조.
PG 수수료 0%, 정산 대기 0일, 카드사 심사 0일. 계좌이체·현금·메신저 송금·상품권·제휴 코드 무엇이든 "돈이 들어온 사실"만 확인하면 된다.

### 3.2 이번에 추가된 것 (코드)

| 구성 | 위치 |
| --- | --- |
| 코드 엔진 (발급·정규화·해시·상태·시도제한·지급 트랜잭션·대사) | `src/lib/redeem.ts` |
| 사용자 화면 `/redeem` | `src/app/redeem/page.tsx`, `src/components/payments/RedeemForm.tsx` |
| API `POST/GET /api/redeem`, `POST/GET /api/redeem/status` | `src/app/api/redeem/*` |
| 운영 콘솔 패널(발급·폐기·대사) | `src/components/payments/AdminRedeemPanel.tsx` → `/admin` |
| API `GET/POST /api/admin/redeem` | `src/app/api/admin/redeem/route.ts` |
| 회귀 테스트 57개 | `scripts/test-redeem.ts` (`npm run test:redeem`, CI 포함) |
| 데이터 모델 | `RedeemCode`, `RedeemBatch` (`src/lib/types.ts`), `DB.redeemCodes/redeemBatches` |

### 3.3 안전 설계 (중요 — 이게 없으면 그냥 무한 무료 쿠폰이 된다)

- **원문 미저장**: sha256 해시만 저장. 발급 응답에서 한 번만 보이고, 운영 콘솔·로그·목록에도 원문·해시가 나오지 않는다.
- **추측 불가**: 32자리 base32 = 160비트. `O/0`, `I/1/L` 혼동은 입력 시 자동 보정.
- **이중 시도 제한**: 메모리(사용자 10회/시간, IP 30회/시간) + 저장소 실패 집계(재시작·다중 인스턴스 방어). 없는 코드와 귀속 불일치는 같은 404로 응답해 존재 여부를 숨긴다.
- **한 트랜잭션 지급**: 사용 횟수 + 크레딧 원장 + `provider=redeem` 0원 주문 + 감사 이벤트가 한 번의 CAS 커밋으로 반영. 실패하면 아무 것도 안 바뀐다(사용 횟수 포함).
- **지급 화이트리스트**: 아래 4종만 무료 지급한다.
  - `pack-unlock-single` (₩5,900 상당) — 팩 1개 잠금 해제
  - `credits-theme-9900` (30크레딧)
  - `plan-creator-monthly` (Creator Pro 1개월)
  - ~~2인 케미(₩7,900) · 반려동물(₩6,900)~~ → 생성 원가가 더 드는 상품이라 무료 경로에서 제외 (`REDEEMABLE_*` in `src/lib/pricing.ts`)
- **운영 통제**: 유효기간(기본 365일, 최대 3년), 예약 발급, 다회 사용, 계정 귀속 발급(CS 재발급), 묶음 단위 폐기, 30일 내 만료 알림 카운터.
- **개인정보**: 계정 삭제 시 귀속 사용자 ID·IP 해시를 제거하고 남은 코드는 계속 유효.

### 3.4 운영 절차 (하루 10분)

1. 판매 채널에 상품표를 올린다 — 예: "단건 완성권 5,900원 / 30크레딧 9,900원 / Creator Pro 19,900원", 계좌 `○○은행 123-456-○○○○○ (예금주)`, 문의 메일.
2. 입금 확인(은행 앱) → `/admin` → **교환권 발급 · 대사** → 상품 선택 → `1개 발급` → **전체 복사** → 구매자에게 전달(카톡/메일).
   - 주문번호·입금자명을 **메모**에 남긴다 → 나중에 대사할 때 이게 유일한 근거다.
   - 특정 계정에만 쓰게 하려면 **귀속 계정 이메일**을 넣는다.
3. 구매자는 `/pricing` → **교환권 사용** 또는 `/redeem` 에서 코드 입력 → 즉시 지급.
4. 매일: `/admin` 대사 카드에서 **발급/사용/잔여/지급 크레딧**을 보고, 입금 내역과 건수를 맞춘다.
5. 환불 요청: 아직 안 쓴 묶음은 **남은 코드 폐기** 후 환불. 이미 사용된 코드는 `docs/PAYMENT_OPERATIONS.md` §6 절차를 따른다.

### 3.5 무엇이 자동이고 무엇이 수동인가 (정직하게)

| 자동 | 수동 |
| --- | --- |
| 코드 발급·해시 저장·지급·원장·주문·감사 로그·폐기·대사 집계 | **입금 확인**, 코드 전달, 세금계산서/현금영수증 발급 |

> 즉 "자동 결제"가 아니라 **"반자동 인도"** 다. 대신 사업자 없이, 수수료 0원으로, 오늘부터 매출이 발생한다.
> 건수가 늘어 자동화가 필요해지는 시점(대략 월 50건)이 PG를 붙일 시점이다.

## 4. 무료로 매출을 만드는 조합 (조합별 비용·리스크)

| 조합 | 필요 조건 | 비용 | 걸리는 시간 | 리스크 |
| --- | --- | --- | --- | --- |
| **A. 교환권 + 무료체험(현행)** | 없음 | 0원 | 0일 | 입금 확인 수작업, 세금 신고는 별도 |
| **B. A + 리워드 광고(AdSense/AdFit)** | 없음 | 0원 | 1일 | 광고 수익은 작다(수천~수만원/월). 앱 심사 시 광고 정책 확인 |
| **C. A + 앱인토스/스토어 선물코드** | 스토어 개발자 계정 | 계정비(플레이 $25 1회) | 1~3일 | 디지털 상품은 IAP 정책상 웹결제 우회 금지 — 앱 안에서는 교환권만 |
| **D. 제휴·체험단 코드** | 제휴처 1곳 | 0원 | 즉시 | 무료 지급이므로 원가 상한(`TRIAL_*`)을 반드시 함께 본다 |
| **E. 개인사업자 등록 → 토스** | 사업자등록(1~3일) + 전자계약 + 카드사 심사(최대 10~14영업일) | 가입비 0원(공시 기준), 카드 1.9~3.4% | 2~4주 | 통신판매업 신고·사업자 정보 표시 필수(없으면 심사 반려) |
| **F. 포트원 Free + 토스** | E와 동일 + 포트원 계정 | 포트원 0원(월 5천만 미만), PG 수수료 별도 | E와 동일 | PG를 바꿀 때 코드 수정 없이 채널만 교체 가능 |

**권장 순서: A → (B/C/D 중 하나) → E/F.**
E를 기다리는 동안 A로 매출·가격·전환 데이터를 쌓으면, PG를 붙이는 순간 바로 매출이 나온다. (지금은 키가 없어서 **가격 검증 자체가 불가능한 상태**였다.)

## 5. 사업자등록 전에 반드시 알아야 할 것 (리스크)

1. **통신판매 신고**: 계속적·반복적 유상 거래를 하면 통신판매업 신고 대상이다. 사업자등록이 선행 조건이고, 신고번호 없이는 PG 심사도 통과하지 못한다. 교환권으로 소액·간헐적으로 시작하더라도 **반복 판매가 확인되면 신고 대상**이므로, 매출이 잡히기 시작하면 바로 정리하는 편이 안전하다.
2. **세금**: 부가통신/일반 과세 여부와 무관하게 매출은 신고 대상이다. 교환권 판매 대금도 매출이다 — 입금 내역을 반드시 남긴다(운영 콘솔 메모 + 통장).
3. **청약철회·환불**: `/refund` 정책을 그대로 적용한다. 코드 미사용 + 7일 이내면 전액 환불이 기본, 이미 사용한 디지털 콘텐츠는 제한 가능. 정책 문구를 판매 채널에도 동일하게 적는다.
4. **미성년자**: 만 14세 미만 가입은 이미 차단되어 있다(`src/lib/auth.ts`). 교환권 판매도 성인 확인을 안내한다.
5. **앱 안에서는 카드결제 금지**: TWA(플레이 앱)에서는 `uaIsTWA` 로 디지털 상품 결제를 이미 차단하고 있다. 교환권도 앱 안에서 "현금 결제"를 유도하는 UX는 스토어 정책 위반이 될 수 있어, **교환권 안내는 웹에서만** 노출한다.
6. **AI 생성 원가**: 교환권은 "돈을 안 받고 푸는 것"과 헷갈리기 쉽다. 무료 지급도 생성 원가가 나가므로 `TRIAL_IMAGES_PER_DAY`·`AI_COST_CAP_KRW` 상한을 유지한다. (컷당 약 54원 가정, `/admin` 원가 표시와 동일)

## 6. PG를 붙일 때 "돈이 안 드는" 설정 체크리스트

`npm run preflight:payments` 가 아래를 자동 검사한다. 사람이 확인할 항목은 마지막 4개.

- [ ] `PAYMENT_PROVIDER=toss`
- [ ] `NEXT_PUBLIC_TOSS_CLIENT_KEY` / `TOSS_SECRET_KEY` — **같은 상점·같은 환경(live/test)** 쌍
- [ ] 저장소: `FIREBASE_*`(Firestore) 또는 `KV_REST_API_*`(Upstash) — **파일 저장소는 결제에 사용 불가**
- [ ] `NEXT_PUBLIC_SITE_URL` = HTTPS 실도메인
- [ ] 사업자 정보 6종(`NEXT_PUBLIC_BUSINESS_*`) + `NEXT_PUBLIC_SUPPORT_EMAIL`
- [ ] `ADMIN_PASSCODE`(운영 콘솔), `DEMO_MODE=0`, `RATE_LIMIT_DISABLED=0`
- [ ] `npm run test:payments` · `test:checkout` · `test:checkout:suspended` 통과
- [ ] 토스 상점관리자에서 **카드 외 수단 비활성**(가상계좌·브랜드페이·커스텀)
- [ ] 실제 테스트 키로 PC·모바일 결제 → 취소 → 새로고침 → 중복 클릭 시나리오 1회씩
- [ ] 미지급 복구·환불 접수 리허설 1회 (`docs/PAYMENT_OPERATIONS.md` §4·§6)

### 무료 인프라로 저장소 맞추기 (중요)

결제는 **영속 CAS 저장소가 필수**인데, 이걸 유료 DB로 할 필요는 없다.

| 저장소 | 무료 한도 | 이 앱에 충분한가 |
| --- | --- | --- |
| Cloudflare KV | 1GB 저장 / 10만 읽기·1천 쓰기/일(무료) | TWA 배포 시 기본. 쓰기 1천/일이 병목 → 스냅샷 1건 구조라 트래픽 적을 때 적합 |
| Upstash Redis (Vercel KV) | 500K 명령/월, 256MB | 초기 매출 규모에 충분 |
| Firestore | 1GiB 저장 / 5만 읽기·2만 쓰기/일 | 결제·원장 검증에 가장 안정적. **권장** |

→ 지금 구조는 `STORE_BACKEND=auto` 로 Firestore → KV → 파일 순 폴백이므로, **무료 한도 안에서 결제를 돌릴 수 있다.** 비용이 발생하는 건 저장소가 아니라 AI 생성 원가뿐이다.

## 8. FAQ

**Q. 교환권만으로 "결제 시스템"이라고 할 수 있나?**
A. 결제(PG)는 아니고 **인도(fulfillment) 시스템**이다. 다만 사용자 입장에서는 "돈 내고 코드 받고 바로 상품 받는" 동일한 경험이고, 회계·원장·복구·대사는 이미 PG 수준으로 남는다. PG가 붙으면 같은 `/api/redeem` 옆에 `/api/checkout` 이 그대로 쓰인다.

**Q. 코드가 유출되면?**
A. 160비트 난수라 추측은 불가능하고, 유출됐다면 `/admin` 에서 묶음 단위로 즉시 폐기한다. 이미 사용된 코드는 지급이 끝났으므로 폐기 대상이 아니다.

**Q. 무료로 열어 주는 게 손해 아닌가?**
A. 손해를 막는 장치가 3개 있다 — ① 단건 완성권만 허용(2인·반려동물 제외) ② 코드당 1회 ③ 발급은 운영자만. 여기에 `TRIAL_*` 원가 상한이 그대로 걸린다.

**Q. 지금 바로 매출을 만들려면 무엇부터?**
A. `/pricing`·`/redeem`·`/support` 에 판매 안내와 계좌를 넣고, `/admin` 에서 코드 3개를 발급해 지인 1명에게 실제로 팔아 보는 것. 이 한 바퀴가 전환율·가격·CS 절차를 한 번에 검증한다.
