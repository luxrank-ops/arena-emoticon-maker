# 구현 현황 점검 (2026-10-30)

이 문서는 코드 정적 점검 결과다. 이전 대화의 '완료', '배포 가능', '앱인토스 연동'이라는 표현은 검증된 사실이 아니다. 실제 외부 서비스나 프로덕션 배포는 확인하지 않았다.

## 확인 결과

- 저장소에 Next.js 앱, Prisma 스키마, 관리자 페이지, Stripe·토스페이먼츠 코드, BullMQ/이미지 생성 코드, Docker 및 CI 파일은 존재한다. 파일 존재가 기능의 완성을 의미하지 않는다.
- 별도 `index.html`은 Next.js 앱과 별개다. Gemini 이미지 생성 요청을 직접 보내도록 수정되었지만 API 키를 가진 실제 호출로 검증하지 못했다.
- 앱인토스 SDK·인증·결제·토스 콘솔 등록/심사에 필요한 통합은 확인되지 않았다. 일반 웹용 토스페이먼츠 위젯은 앱인토스 등록이나 앱인토스 결제 연동 자체가 아니다. 앱인토스 가이드와 서비스 유형에 맞는 결제 정책을 먼저 확인해야 한다.
- 토스페이먼츠 결제는 서버 주문 저장/소유권 검증 없이 클라이언트 금액을 승인하고 대략적인 금액 계산으로 크레딧을 지급하며 구독 발급은 미완성이다. 위젯은 서버 주문 생성을 우회한다. 웹훅 인증 방식도 공식 문서와 대조 검증되지 않았다. 따라서 신규 토스 주문/승인과 웹훅 자동 처리는 잠정 차단했으며 실제 운영에 사용하면 안 된다. 기존 거래가 있다면 운영자가 토스 콘솔에서 별도로 대사해야 한다.
- Prisma 클라이언트는 `NODE_ENV=production`에서 실제 DB 대신 모의 클라이언트를 사용했다. 제거했다. 이제 DB 설정이나 클라이언트 생성이 잘못되면 오류가 드러난다.
- 기존 이월 계산은 미사용 잔액을 추적하지 않고 중복 지급할 수 있었다. 크론 경로와 워커 스케줄을 중지했다. 이월 기능은 미구현이다.
- 이미지 큐는 실패한 매 재시도마다 환불했다. 최종 실패에서만 상태 변경과 환불을 함께 수행하도록 수정했다. 그러나 생성 요청의 차감·레코드 생성·큐 등록은 원자적이지 않아 큐 오류 시 손실 및 동시 요청 문제가 남아 있다.
- 관리자 설정 저장에 TODO가 있으며 일부 관리 동작은 화면만 존재한다. 알림/Sentry 코드 존재와 실제 설정·발송 검증은 별개다.
- Phase 3에서 제안된 A/B 테스트, 마켓플레이스, 공개 API, 이메일 캠페인, 부하 테스트 등은 구현 완료로 확인되지 않았다.
- Prisma migrations 디렉터리가 없으며, 실제 PostgreSQL 스키마 상태도 확인하지 못했다. Next.js의 보안 업데이트가 필요하다.
- Docker/CI는 pnpm lockfile을 요구하지만 저장소에는 npm lockfile만 있다. Dockerfile은 standalone 출력 설정과 `public` 디렉터리를 가정하며 일부 명령에 RUN이 없어 그대로 배포 준비가 된 상태가 아니다. 워커 컴파일 결과도 Node의 별칭/ES module 해석을 검증해야 한다.
- Stripe 결제/웹훅, 환불, 잔액 정확성, DB·Redis·스토리지 연결, 백업·모니터링·실제 배포는 외부 자격증명과 서비스가 없어 통합 검증하지 못했다. 유료 서비스 오픈 전 재시도/중복/부분 환불을 포함한 거래 원장과 통합 테스트가 필요하다.

## 이번 점검의 검증 범위

의존성 설치 후 `prisma generate`를 시도했으나 샌드박스에서 `binaries.prisma.sh` 접근이 제한되어 실패했다. 따라서 빌드/타입 검사 및 실제 DB·결제·이미지 생성 E2E 성공을 주장할 수 없다.

## 출시 전 우선순위

1. 결제/크레딧 원장, 주문 소유권·금액 검증, 멱등 처리, 환불과 대사, 생성 큐 보상 로직 및 통합 테스트.
2. 앱인토스 공식 가이드에 따른 앱 등록·SDK·로그인·결제 및 검수 요건 확인 (일반 토스페이먼츠와 구분).
3. 검증된 DB 마이그레이션, 보안 업데이트, 재현 가능한 CI와 Docker/워커 실행 테스트.
4. 테스트/운영 환경 분리, 시크릿, 모니터링, 백업·복구, 개인정보 정책과 사업자/결제 심사.

## 추가 조치

- 독립형 이미지 제작 화면에서 브라우저에 API 키를 저장하지 않도록 변경하고 이전 저장 키를 제거한다. 입력한 키는 사용자의 브라우저에서 Google로 직접 전달된다.
- 비밀번호를 검증하지 않던 이메일 로그인 제공자를 제거하고, 로그인 화면에서 안내한다. OAuth 자격증명과 DB가 설정된 경우에만 Google/GitHub 로그인을 사용할 수 있다.
- 세션 크레딧과 역할을 클라이언트 입력 대신 DB에서 읽도록 변경했다. 이미지 상태 조회 시 소유권 확인에 필요한 userId 누락을 수정했다.
- 독립형 UI의 이미지 표시/다운로드 흐름은 모의 API 테스트(`node tests/standalone-smoke.cjs`)를 통과했다. 실제 Gemini 호출은 API 키가 없어 검증하지 못했다.
