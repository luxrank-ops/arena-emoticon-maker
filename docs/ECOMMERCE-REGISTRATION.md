# 통신판매업 신고번호 — 발급·표기 가이드 (전자상거래법 §13)

> 사용자가 묻는 "전자상거래 등록번호" = **통신판매업 신고번호**다.
> 이 서비스는 **디지털 콘텐츠를 반복 판매**하므로 원칙적으로 신고 대상이다.
> 면제 요건(간이과세자 또는 직전연도 거래 50회 미만)에 해당하면 번호 대신 "면제 대상"으로 표기한다.

---

## 1. 이 앱에서 필요한 이유 (3곳)

| 요구 주체 | 근거 | 없으면 |
| --- | --- | --- |
| **전자상거래법 §13** | 사이버몰 초기화면에 상호·대표자·주소·전화·이메일·사업자등록번호·**통신판매업 신고번호** 표시 | 과태료(최대 500만원) |
| **PG(토스) 심사** | 카드사 심사 체크리스트 | 심사 반려/지연 (`docs/TOSS_PAYMENTS_SETUP.md`) |
| **구글 플레이 심사** | 스토어 목록·판매자 정보 | 판매자 프로필 검증 지연 |

현재 앱은 **푸터 + 요금제 화면**에 표시한다(`src/lib/business.ts` → `mailOrderLabel()`). 운영 콘솔이나 영수증에도 같은 값을 쓴다.

---

## 2. 신고 대상인가? (2026 기준)

- **원칙**: 인터넷으로 상품(디지털 콘텐츠 포함)을 계속 판매하면 신고 대상.
- **면제**: 다음 중 하나면 면제
  - **부가가치세법상 간이과세자** (직전연도 공급대가 1억 400만원 미만, 업종별 기준)
  - **직전연도 통신판매 거래 50회 미만**
- 주의: 면제여도 **PG·오픈마켓이 신고증을 요구하는 경우가 많다.** 일반과세자로 전환되거나 거래가 50회를 넘으면 즉시 신고 대상.
- 매년 **등록면허세 12,000~40,500원**(지자체 인구 규모별)이 부과된다. 신고 수수료는 없다.

> 출처: 정부24 안내 및 2026년 정리 자료 — [면제·절차](https://guidepro.co.kr/guides/tongsin-panmaeup-singo/), [등록면허세·주소 공개](https://ieodaon.com/blog/ecommerce-registration-privacy-policy)

## 3. 발급 절차 (사업자등록 → 신고 → 번호)

1. **사업자등록** (홈택스, 1~3일). 개인사업자면 충분하다.
2. **구매안전서비스 이용확인증** 확보
   - PG 계약(토스) 후 PG사에서 발급, 또는 은행·에스크로 서비스에서 발급.
   - 정부24 신고 시 **필수 첨부**.
   - PG 계약 전이라면: 은행의 "구매안전(에스크로) 서비스" 가입 후 확인증을 받는 경로가 있다.
3. **정부24 → "통신판매업 신고"** 검색 → 온라인 신청
   - 입력: 상호, 대표자, 사업장 주소, 판매 방식(인터넷), 취급 품목(디지털 콘텐츠·이모티콘), 결제 수단, **대표 도메인**(`emotihak.com`), 호스트 서버 소재지.
   - **호스트 서버 소재지**는 배포 위치를 적는다(예: Cloudflare/Vercel 리전 — `vercel.json` 은 `icn1`).
4. **영업일 2~3일** 처리 → 관할 구청 문자 통보.
5. **위택스/이택스에서 등록면허세 납부** → 정부24에서 **신고증 출력**(출력 가능 기간이 짧으니 즉시 저장).

## 4. 번호 형식 (지자체마다 다르다)

| 예시 | 쓰는 곳 |
| --- | --- |
| `2026-부산강서구-0693` | 부산 강서구 (현재 코드 기본값) |
| `제2026-서울마포-0123호` | 서울 일부 자치구 |
| `2026-000123` | 일련번호만 쓰는 지자체 |

- **규칙: 신고증에 적힌 문자열을 그대로** 넣는다. 우리가 형식을 만들지 않는다.
- 화면 표기는 `통신판매업신고: <번호>` + `[사업자정보확인]`(국세청 홈택스 링크) 조합이 관행이다.
- 코드는 다음 느슨한 패턴만 검사한다: `연도 - 지역/일련 - 번호` (`npm run preflight:payments`).

## 5. 이 저장소에 넣는 방법

```bash
# .env.local (또는 배포 Secret/Variable)
NEXT_PUBLIC_BUSINESS_NAME=아모가
NEXT_PUBLIC_BUSINESS_OWNER=이춘학
NEXT_PUBLIC_BUSINESS_REG_NO=212-77-00245
NEXT_PUBLIC_BUSINESS_ADDRESS=부산광역시 강서구 …
NEXT_PUBLIC_BUSINESS_TEL=010-2846-8906
NEXT_PUBLIC_SUPPORT_EMAIL=luxrank@gmail.com
# ↓ 신고증에 적힌 그대로
NEXT_PUBLIC_MAIL_ORDER_NO=2026-부산강서구-0693
```

면제 대상이면 번호 대신:

```bash
NEXT_PUBLIC_MAIL_ORDER_EXEMPT=1     # 화면에 "통신판매업 신고 면제 대상"으로 표시
```

확인:

```bash
npm run preflight:payments     # 형식·누락 검사 (값 자체는 출력하지 않음)
npm run test:launch            # 표시 의무 정적 점검
```

> `src/lib/business.ts` 의 기본값은 **운영 정보 예시**다. 배포 전 실제 신고증과 **문자 단위로 대조**해야 한다.
> 번호가 틀리면 전자상거래법 위반이고 PG·스토어 심사에서도 반려된다.

## 6. 신고 후 해야 하는 일

- [ ] 초기화면(푸터)에 7개 항목 표시: 상호 · 대표자 · 주소 · 전화 · 이메일 · 사업자등록번호 · 통신판매업 신고번호
- [ ] **사업자정보확인** 링크(홈택스) 연결 — 이미 연결됨
- [ ] 매년 등록면허세 납부(위택스)
- [ ] 주소 변경·폐업 시 **변경 신고**(30일 이내)
- [ ] 환불 정책(`/refund`)·이용약관(`/terms`)에 사업자 정보와 일치하는지 확인
- [ ] 스토어 목록·PG 계약서의 사업자 정보와 동일하게 유지

## 7. 자주 하는 실수

| 실수 | 결과 |
| --- | --- |
| 번호를 예시로 남겨 두고 출시 | 전자상거래법 위반 + PG 심사 반려 |
| 신고증과 띄어쓰기·`제`·`호` 불일치 | 심사 담당자가 확인 불가로 반려 |
| 사업장 주소를 집 주소로 신고 | **주소가 그대로 공개**된다 → 사무실·가상오피스 고려 |
| 간이과세자 면제인데 번호를 지어냄 | 허위 표시. 면제면 `NEXT_PUBLIC_MAIL_ORDER_EXEMPT=1` 로 표기 |
| 신고만 하고 등록면허세 미납 | 매년 가산세·체납 |
| 사업자등록 전에 신고 시도 | 접수 자체가 안 된다(사업자등록 선행 필수) |
