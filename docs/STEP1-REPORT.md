> **해석:** 시장은 이미 "결제 의사가 검증된" 성숙 시장입니다. 우리가 새로 만들어야 하는 것은 수요가 아니라
> **공급 자격**(그림 실력)입니다. 70만 개 중 상위 2,885개(0.4%)가 1억 원을 벌었다는 사실은,
> *"아무거나 만들면 안 되고 성공 공식대로 만들어야 한다"* 는 뜻이며, 이는 곧 **추천 시스템의 가치**입니다.

### 1.2 메가 히트 이모티콘의 성공 방정식 (분해)

상위권 이모티콘을 감정·상황·구조로 분해한 결과, 공통 분모는 다음 5가지입니다.
이 5가지를 **제품의 생성 규칙**으로 그대로 코드화합니다.

| # | 성공 요인 | 관찰 | 제품 반영 |
| --- | --- | --- | --- |
| 1 | **상황 밀착성** | "출근", "야근", "점심 뭐 먹지", "월급 들어옴" 등 하루 동선에 붙은 대사가 반복 사용을 만든다 | `SituationTemplate` 카탈로그 120종을 요일·시간대에 매핑 |
| 2 | **3초 판독 표정** | 작은 화면에서도 감정이 즉시 읽히는 과장된 입·눈 | `EmotionIntensity` 다이얼(0~100) → 프롬프트 강도 파라미터 |
| 3 | **만능 컷 비율** | 세트의 20%는 "어디든 쓰는 무난한 컷"(ㅇㅋ, 굿, 웃음) | 팩 구성 자동 배분 규칙 (만능 5 : 상황 15 : 반응 4) |
| 4 | **캐릭터 일관성** | 얼굴/비율이 흔들리면 세트 전체가 무너진다 | **Identity Lock**: 캐릭터 시트 1장 고정 후 24컷 파생 |
| 5 | **말맛(대사)** | 같은 그림도 대사 한 줄로 히트가 갈린다 | 톤 프리셋 6종(무뚝뚝/애교/킹받음/사회생활/ MZ/정색) × LLM 문구 생성 |

### 1.3 경쟁 지형과 빈틈

| 유형 | 대표 | 강점 | 빈틈 (=우리 진입점) |
| --- | --- | --- | --- |
| 카메라/뷰티 앱 | 스노우·Lensa·Remini 계열 | 필터 품질, 대형 MAU | **이모티콘 "팩"으로 쓰이지 않음** — 결과물이 SNS 사진용 1장에 그침 |

## 2. 제품 정의

### 2.1 포지셔닝

> **이모티미 = 나의 얼굴로 만드는 '대화용 무기'.**
> 사진첩에 쌓이는 예쁜 그림이 아니라, **오늘 카톡에서 실제로 쓰이는 3초**를 파는 서비스.

### 2.2 사용자 여정 (핵심 6스텝)

```
[1] 셀피 1장 업로드 (온디바이스 품질/얼굴 검증)
     └ 정면·단독 인물 확인, 라이브니스 체크, EXIF 제거
[2] 톤 선택: 실사풍 / 3D 카툰 / 2D 귀여움 / 수채 / 흑백 / 개그 캐리커처
[3] Identity Lock → 캐릭터 시트 생성 (정면·3/4·측면)  ← 사용자가 1개 선택/재생성
[4] 24컷 자동 생성 (표정 × 상황 템플릿) + 진행률 스트리밍
[5] 인앱 편집기: 대사 입력 · 감정선 다이얼 · 소품/스티커 · 배경 · 애니메이션
[6] 내보내기: 카톡 공유용 PNG/GIF ZIP · 카카오 제안 규격 패키지 · 굿즈 주문
```

### 2.3 벤치마킹 추천 시스템의 작동 방식

사용자가 "무엇을 만들지" 고민하지 않게 만드는 것이 전환율의 핵심입니다.

- **입력**: 시간대, 요일, 날씨(선택), 사용자가 고른 기분 1개, 최근 사용한 컷(로그)
- **매칭**: 120종 `SituationTemplate`을 (시간대 × 감정 × 관계) 3축 벡터로 임베딩 → 코사인 유사도 상위 24개
- **보정**: 만능 컷 5개 강제 포함(성공 방정식 #3), 중복 감정 상한선 적용
- **결과**: "오늘의 추천 팩 24컷" — **사용자가 템플릿을 고르는 게 아니라, 템플릿이 먼저 도착**

## 3. 킬러 기능 4종 (Innovation Think-Tank 주도)

> 요구사항: "기존 이모티콘 앱에 없던 새로운 방식" 최소 2개를 코드 베이스에 반영.
> 아래 4종 중 **①②③은 Step 2에서 실제 코드로 구현**, ④는 Step 2 후반 구현.

### ① 오늘의 얼굴 브리핑 — Daily Face Brief
**무엇:** 매일 07:30, 오늘의 요일·날씨·사용자 기분을 반영한 **8컷을 자동 큐레이션**해 푸시.
**왜:** 이모티콘 앱의 최대 약점은 "한 번 만들고 안 들어온다". 매일 아침 이유를 만들어 D7 리텐션을 방어.
**어떻게 (코드):** `cron(07:30 KST)` → 추천 엔진 → 이미 보유한 표정 뱅크에서 **재합성만** 수행(생성 비용 0원) → Web Push.
**차별점:** 신규 생성이 아니라 **재조합**이므로 원가 없이 매일 새 콘텐츠. 구독 정당화의 핵심.

### ② 톡 붙여넣기 3초 답장 — Chat-to-Sticker
**무엇:** 카톡 대화를 복사해 붙여넣으면, 그 맥락에 맞는 **내 얼굴 이모티콘 3장 + 대사**를 2초 안에 제시.
**왜:** 사용자가 이모티콘을 "만드는" 순간은 없다. **"쓰는" 순간**에 개입해야 한다.
**어떻게 (코드):** LLM이 의도 분류(사과/거절/웃김/축하/킹받음…) → 24컷 뱅크에서 최적 프레임 선택 →
서버 canvas 합성으로 대사 오버레이 (이미지 생성 API 호출 없음 → **지연 0.5~1.5초, 원가 0원**).
**차별점:** 경쟁 앱은 모두 "생성" 지향. 우리는 **실사용 순간 삽입** 지향.

### ③ 스티커 → 굿즈 — Sticker-to-Goods
**무엇:** 마음에 든 컷을 아크릴 스탠드·포토카드·머그·스티커 팩으로 원클릭 인쇄 주문.
**왜:** 구독 피로도를 우회하는 **고마진 현금 흐름**. 내 얼굴 굿즈는 선물 수요(생일·기념일)로 확장.
**어떻게 (코드):** `GoodsProduct` 카탈로그 + POD 위탁 파트너 어댑터 + 주문/배송/교환 정책 + 재주문.
**리스크 대응:** 물류·CS 부담 → DevOps 의견 반영, **POD 위탁(재고 0)** + 첫 3개월은 주문 즉시 제작.

### ④ 카카오 제안 패키저 — Packager (후순위)
**무엇:** 만든 팩을 카카오 이모티콘 스튜디오 제안 규격(**24종 360×360, 개당 2MB 이하**)으로 자동 검증·리사이즈·ZIP 패키징 + 제안서 텍스트 생성.
**왜:** "내가 만든 게 진짜 상품이 된다"는 아티스트 각도 → Pro 티어의 결정적 페이월.
**어떻게 (코드):** `export` 파이프라인 with 스펙 검증기(사이즈/용량/투명도) + 실패 사유 리포트.

```
   │  · MediaPipe FaceLandmarker (WASM, 온디바이스) → 468 랜드마크/품질/라이브니스
   │  · 편집기: Canvas + Konva (레이어 · 텍스트 · 소품 · 감정선 다이얼)
   ▼
[API 계층]  Next Route Handlers + Zod 검증 + 세션(토스 로그인/NextAuth)
   ├─ /api/face/analyze        얼굴 품질·특징점 (원본 미저장 모드 지원)
   ├─ /api/character-sheet     Identity Lock 1단계 (시트 1장 생성)
   ├─ /api/packs               팩 생성 (24컷) — Job 큐 등록, SSE 진행률
   ├─ /api/reply               Chat-to-Sticker (뱅크 매칭 + 즉시 합성)
   ├─ /api/brief               Daily Face Brief (cron 트리거/조회)
   ├─ /api/export              카카오 규격 검증·ZIP 패키징
   ├─ /api/checkout·webhook    토스페이먼츠 결제/빌링/웹훅 (Provider 추상화)
   ├─ /api/goods               굿즈 카탈로그·주문
   └─ /api/admin               운영 대시보드 (KPI·모더레이션·환불)
   ▼
[워커 계층]  BullMQ + Redis : 이미지 생성 잡 · 후처리(sharp/ffmpeg) · 파기 스케줄러
   ▼
[데이터]  PostgreSQL(Prisma) · Redis(큐/캐시) · S3·R2(프리사인드, 24h TTL)
[AI]     Gemini 2.5 Flash Image (Identity Lock / 캐릭터 일관성) + Gemini Flash (의도 분류·대사 생성)
[관측]   Sentry · PostHog · 구조화 로그 · /api/health · GitHub Actions
```

**설계 원칙 3가지**
1. **원본 얼굴은 24시간 뒤 반드시 사라진다** — 서버는 원본을 장기 보관하지 않고, 생성 결과물과 파생 벡터만 남깁니다.
2. **생성은 비싸고, 조합은 공짜다** — "생성"은 팩 제작 시 1회, "사용"은 뱅크 재조합으로 처리.
3. **결제 수단은 갈아끼울 수 있다** — `PaymentProvider` 인터페이스로 토스 결제위젯 / 빌링키 / 앱인토스 IAP / Mock 4종을 런타임 교체.

상세 설계는 [docs/ARCHITECTURE.md](ARCHITECTURE.md) 참조.
