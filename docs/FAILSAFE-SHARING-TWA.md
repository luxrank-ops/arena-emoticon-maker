# Fail-safe 분석 · 카카오 공유 · TWA 출시 명세

> 2026-11-06 구현 기준. 실제 코드와 Console/실기기 검증이 필요한 항목을 구분한다.

## 1. 단계별 분석과 예외 처리

### 파이프라인

1. **브라우저 1차 분석:** MediaPipe FaceLandmarker가 468개 랜드마크, 얼굴 위치·크기·밝기·선명도를 계산한다. WASM/스크립트 로드에 실패하면 기존 Canvas 색상 분석으로 자동 대체한다.
2. **서버 2차 검토:** Gemini에 원본을 요청 본문으로만 전달해 시각적 특징을 추출하고 다시 검증한다. 기본 모델은 `gemini-flash-latest`, 요청은 temperature 0·JSON 응답·512 출력 토큰·8초 제한이다.
3. **대체 경로:** 500/429 등 HTTP 실패 시 Vertex AI 경로를 한 번 시도한다. 타임아웃, 양쪽 요청 실패, JSON 파싱/스키마 오류는 `prepareWithFallback`에서 기본 검증으로 전환한다. 기본 검증은 형식·해상도만 확인하며 AI가 추출한 헤어/안경 특징을 사용하지 않는다.
4. **사용자 안내:** 기본 검증으로 전환하면 업로드 진행 화면에 즉시 노란색 상태 안내를 표시하고, 이후 `ConsistencyNotice`에도 같은 제한을 남긴다. 기본 분석을 AI 신원 검증 성공으로 표시하지 않는다.

| 상황 | 코드/조건 | 동작 |
|---|---|---|
| 오프라인 | `OFFLINE`, `navigator.onLine === false` | 네트워크 요청을 중단하고 세션 사진으로 재시도 제공 |
| 사진 없음 | `ERR_IMG_MISSING` | 사진 선택으로 복귀 |
| 지원하지 않는 형식 | `ERR_IMG_INVALID_FORMAT` | JPG/PNG/WebP 선택 안내 |
| 과도한 데이터 | `ERR_IMG_TOO_LARGE` | 사진 축소/재선택 안내 |
| 얼굴 미검출 | `NO_FACE`, UI 표준화 `ERR_ANALYZE_NO_OBJECT` | 밝은 정면 재촬영 가이드 |
| 흐림/AI 검토 필요 | `BLUR`, `ERR_ANALYZE_BLURRY`, 기존 `PHOTO_NEEDS_REVIEW` | 얼굴 가이드와 재촬영 동작 |
| 서버/네트워크 실패 | `ERR_SERVER_FAIL` 또는 기존 5xx 도메인 코드 | 세션 사진 ID와 실패 코드만 보관한 수동 재시도 |

- 기존 `PHOTO_NEEDS_REVIEW`, `CONSISTENCY_UNAVAILABLE`, 결제·권한 코드는 유지한다.
- 재시도는 원본 사진을 복제 저장하지 않는다. 기존 세션 사진을 사용하며 새 사진을 선택하거나 생성에 성공하면 대기 정보를 지운다.
- 진행 UI는 전역 `loading.tsx`가 아니라 기존 `GenerationProgress`를 사용해 분석 단계와 실제 진행률을 보여준다.

## 2. 카카오 공유

### 항상 제공되는 대체 동작

- `navigator.share({ files, title, text })`로 완성 PNG 한 개와 `이모티학 [표정명] 이모티콘 + 대사`를 시스템 공유창에 전달한다.
- 파일 공유가 불가하면 링크 시스템 공유, 링크 복사, PNG 다운로드 순으로 대체한다.
- 원본 사진, 랜드마크, 팔레트, 품질 점수, 성격 유형, 제작 설정은 공유하지 않는다.

### 설정된 경우에만 사용하는 Kakao Feed

`NEXT_PUBLIC_KAKAO_JS_KEY`가 있을 때만 Kakao SDK를 로드한다. Kakao 개발자 콘솔에 실제 배포 도메인을 등록해야 하며, 결과 이미지 URL은 Kakao 서버가 공개적으로 읽을 수 있어야 한다.

Feed 내용:

- 제목: `이모티학 [표정명] 이모티콘 도착! 🎉`
- 설명: `사진 속 내 표정으로 만든 나만의 이모티콘과 대사 문구를 확인해 보세요.`
- 이미지: 완성 컷 전용 공개 URL, 1:1 비율
- 버튼: `결과 보기`, `나도 만들기`
- 두 링크 모두 `utm_source=kakaotalk&utm_medium=share&utm_campaign=emoticon_share` 사용

SDK 호출은 **공유 창을 연 것**이지 메시지 전송 완료가 아니다. 키 부재, SDK 로드 실패, 도메인 미설정 시 시스템 공유/복사/PNG로 전환하며 직접 전송 성공을 표시하지 않는다.

### 비회원 결과와 보안

- 결과 경로는 예측 가능한 팩 ID가 아니라 **`/share/[43자 무작위 토큰]`**이다.
- 소유자만 `POST /api/packs/[id]/share`로 생성할 수 있고, 완성 이미지가 있는 한 컷만 연결된다.
- 토큰 원문은 생성 응답에서 한 번만 반환하고 DB에는 SHA-256 해시만 저장한다.
- 링크는 7일 후 만료되며, 소유자가 같은 컷의 링크를 모두 해제할 수 있다. 생성은 사용자별 활성 링크 50개와 요청 속도를 제한한다.
- 매 조회 시 만료·해제·팩 삭제·컷 숨김·이미지 존재를 다시 확인한다. 공개 이미지는 `no-store`이며 결과 페이지는 `noindex, nofollow`다.
- 공유 페이지의 토큰 경로는 분석 페이지뷰에서 제외하고 UTM 세 값만 검증해 세션에 보관한다.
- 결과 페이지는 비회원도 한 컷과 대사만 볼 수 있다. `앱에서 결과 열기`는 Android App Link/Intent를 사용하고 미설치 시 Google Play로 이동한다.

## 3. PWA와 Bubblewrap TWA

### 구현 확인 항목

- `public/.well-known/assetlinks.json`: 패키지 `com.emotihak.app`과 SHA-256 지문을 정적 검사한다. 실제 도메인과 Play 앱 서명 지문은 배포 후 다시 확인해야 한다.
- `public/manifest.webmanifest`: `start_url: /`, `display: standalone`, 192/512/maskable 512 아이콘을 제공한다. `twa/twa-manifest.json`, Gradle, 로컬 매니페스트와 색상을 `#7C4DFF`, `#1A237E`, `#F8F9FA`로 맞췄다.
- `public/sw.js`: 프로덕션에서 등록된다. 정적 오프라인 페이지·매니페스트·아이콘·Next 정적 자산만 캐시한다.
- 모든 페이지 탐색은 네트워크 우선이며 실패 시 `public/offline.html`을 반환한다. 페이지 응답 자체는 저장하지 않는다.
- 인증/API/생성 이미지/공유 토큰과 사적인 페이지는 캐시하지 않는다.
- 침해적 웹 동작을 숨기는 대신, 독립 실행·세로 화면·네이티브 파일/사진 촬영·시스템 공유·오프라인 안내·모바일 편집/납출을 실제 앱 가치로 제공한다.

### 뒤로가기와 권한

- TWA/Chrome의 기본 히스토리 탐색을 유지한다. 업로드 설정↔사진 단계와 생성 중 `popstate`/`beforeunload` 경고는 기존 동작을 유지한다.
- 루트의 자연스러운 종료, 생성 중 뒤로가기 경고, 외부에서 `/share/...`로 들어온 뒤 복귀는 실기기에서 확인한다.
- 현재 사진 촬영은 `getUserMedia`가 아니라 `<input type="file" capture>`를 사용한다. OS 촬영 화면을 열기 전에 목적·전송 시점·권한 선택을 고지하고, 거부 시 사진첩 선택이 가능하다.
- 개인정보 처리방침은 필수 동의 화면과 푸터에 상시 연결된다. 법률 링크를 TWA라는 이유로 제거하지 않는다.

### 접근성 결정

전역 텍스트 선택 금지, 이미지 롱프레스 차단, `user-scalable=no`는 적용하지 않는다. 이들은 Play 필수 요건이 아니며 저시력·읽기·보조 입력 사용자를 방해한다. 더블탭/핀치 확대와 텍스트 선택은 유지하고, 저장이 필요한 이미지에는 명시적 48px 이상의 저장·공유 버튼을 제공한다.

## 4. 출시 전 실기기/Console 체크리스트

- [ ] 배포된 Asset Links가 200/JSON으로 응답하고 업로드·Play 앱 서명 지문이 모두 일치하는가?
- [ ] 남은 주소창 없이 standalone으로 열리고 아이콘·스플래시·상태/내비게이션 색이 맞는가?
- [ ] 비행기 모드에서 새 페이지 탐색 시 오프라인 안내가 나오고, API·사적 결과가 캐시에 남지 않는가?
- [ ] 루트 종료, 내비게이션 뒤로가기, 생성 중 경고가 정상 작동하는가?
- [ ] 사진 촬영 사전 고지→OS 권한/촬영→거부 시 갤러리 대체가 작동하는가?
- [ ] 카카오 도메인 등록 후 Feed 이미지·두 버튼·UTM·비회원 랜딩·App Link·미설치 Play 대체를 확인했는가?
- [ ] 링크 해제, 7일 만료, 팩 삭제, 신고 숨김 후 외부 기기에서 404가 되는가?
- [ ] Lighthouse/실제 네트워크에서 서비스 워커와 오프라인 동작을 확인했는가? 정적 테스트를 Lighthouse Pass로 간주하지 않는다.
- [ ] Play 데이터 안전 양식에 Gemini 전송, Kakao SDK 사용 여부, 공유 링크와 저장 기간을 실제 설정과 일치시켰는가?

## 5. 검증 명령

```bash
npm run typecheck
npm run test:failsafe
npm run test:play:static
npm run build
```

이 명령은 코드·정적 설정을 확인한다. AAB 서명, Play 라이선스/환불, Kakao 실제 전송, 실제 Gemini 유료 호출, Lighthouse 점수, 실기기 동작은 별도 검증이 필요하다.
